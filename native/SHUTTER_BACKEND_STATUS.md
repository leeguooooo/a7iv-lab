# 自定义快门声音后端状态

尚无可安装并经过实机验收的完整后端。目标是自定义快门声音，保留原厂焦点声音；代码编译、控制回复和原生 Start 返回均不等于出声或资源退休。

## 已有源码和验证

- `shutter_wire.c` 提供私有 SHT2 的六类操作与精确40字节回复边界。关联编号为1至65534；保留编号65535被当前CP接收器拒绝。41项检查包括实际CP指令互测。私有测试材料部分缺失时失败，两项均不存在时才跳过可选互测。
- 本机 `output/ap-sht2-transport-port-20261031/` 已派生实际 AP transport C，使用共享编码器，拒绝slot1、旧magic和未定义参数。12项主机C与7项AP A64/CP Thumb互测通过；原生队列、路由和ABI仍使用命名替身。它不是完整resource worker。
- 本机 `output/sound-persistence-fix-20261031/` 保存实际AP配置发布修复。21项真实C故障场景和8项A64检查通过，原始关闭失败回滚缺陷已复现。结果区分未发布、不确定、已持久化仅关闭失败及成功。不确定时阻止后续写入；关闭失败不回滚已经同步的新代。旧800字节runtime ABI不变，新增私有4字节BSS需要装载器清零。独立volume发布者的对应修复在 `output/volume-persistence-fix-20261031/`，55项C检查和9项A64检查通过；两者均未证明中间改名的掉电恢复。
- `output/cp-prepared-abort-20261031/` 增加协商后的未发布上传取消原语，41项新Thumb检查及16项旧回归通过。必须先验证QUERY1能力位；取消保留三个租约和票据高水位，不能释放ACTIVE。完整CP路由和原生提供者仍未验证，不能安装这个研究ELF。
- `output/single-shutter-resource-busy-wrap-20261031/` 已实现私有单快门资源所有者，并连接实际AP转换器、SHT2和CP Thumb组件。72项检查通过。独立12项新旧对照复现并修复了BUSY等待的计数回绕问题。只有明确回复、未提交播放的BIND、PREPARE和协商取消可以有限重试；未知结果、COMMIT和ACTIVE停止不重试。原生分配和传输提供者仍使用替身，正式配置在原生操作前关闭，不能安装。

## 原厂音频消费边界

`output/cp-shutter-completion-20261031/audit.py` 固定原厂CP哈希并执行20项原始Thumb模型检查。调用者和构造器交接的是含音频地址的84字节请求。不能从调用者模型未读波形推导完整原生链绝不复制。

原始Start调用者未核对虚拟交接的返回寄存器，因此Start返回0不能证明投递、播放或退休。状态0x1003明确不清理。周期StartTiming回调与完成回调不同。原型中被解释为Stop依据的caller `0x5dcb67` 实际属于20项声音表导出，不能作为停止证据。

原Exists返回2表示kind已注册，即使记录禁用。模型不能证明实际启动后kind17尚未注册。

`output/cp-stock-sound-registry-20261031/audit.py` 的15项检查恢复了原厂构造、注册、移除和导出路径。同版AP默认配置前段写入kind1至16，没有17，但完整属性加载及启动后实际表仍未知。原厂20行导出即使未注册17也显示17标签，因此标签不能作为可用性证据。实际注册17会让当前私有BIND拒绝；focus kind4保持原生。

`output/cp-channel1-consumer-20261031/audit.py` 又以7项原始指令模型恢复了channel1对象 `0x145b0a0` 虚表 `+0x24` 的真实目标。10e和10f直接分派到原生处理器；处理器保存含数据地址的描述，并写入地址、长度寄存器。一条选定路径在callback(0)后仍执行控制寄存器写入。这不能证明硬件仍在读取，也不能把callback(0)直接当作完整退休fence。剩余缺口是原始状态、控制及ack合同与最后硬件读取的关系；当前禁止回收ACTIVE backing。

旧CP研究组件中 `BA4B65/BA4D61` 等继续点属于历史追加适配区，原厂CP相应位置为零。它们不是已证明的原厂继续地址。下述新组件已移除这两个跳板依赖，但完整镜像和原生提供者仍未验证，零未定义符号不构成部署证明。

`output/cp-stock-receive-envelope-20261031/audit.py` 连续执行原厂worker、接收器、source与length读取及分发器，7项检查通过。接收器释放原始消息前拥有完整负载，之后只向内部请求复制最多72字节，内部`+4`保存source、`+12`起保存负载。原厂分发器拒绝私有cmd7e。owner接收的是原始负载，因此接入原厂路径需要明确的内部请求适配及释放前捕获。本模型的队列入口为合成提供者，未证明AP至CP传输。

`output/cp-stock-adapter-component-20261031/run.py` 已编译实际原厂适配器与原有owner，22项检查通过，两次ELF构建一致。新路由明确传入`request+12`，捕获器在原始消息释放前消费完整COPY。960字节分块在原消息被覆盖后仍正确提交，完整32位source保持不变。普通命令与未修改原厂的回复、寄存器及APSR一致。原厂serializer另由测试入口调用，验证回复长度、目标和source；这不表示已连续执行worker之后的所有分支。新增适配层只在离线模型内替换两个入口，尚未构建完整CP镜像或安装原生hook。

`output/cp-layout-fl23-baseline-20261031/` 核对了实际准备包使用的v7 CP，而非只看原厂CP。v7已允许当前代码位置执行，原厂的XN阻断不适用于该包；owner的128字节仍在启动清零范围外。ELF还包含一个会覆盖212字节原厂非零数据的header PT_LOAD，不能把模型的全部段加载方式用作镜像复制配方。`output/cp-fl23-adapter-compat-20261031/run.py` 改用明确的分节加载，在原厂及v7上各重跑22项，保持这212字节不变。模型仍手工初始化owner，不能当作启动初始化已解决。

`output/cp-dmm-allocator-cycle-20261031/audit.py` 的8项检查连续执行实际分配器、同slot查询和单位释放，替代先前的分配/释放替身。三个成功CLAIM不保证固定物理地址或连续性。flags1获取后，flags2完成匹配释放；错误使用flags0可先释放再返回raw3，因此非零释放结果不能作为“未释放”的证明，也不能自动重试。父backing、CP地址别名及endpoint寿命仍未闭合。

`output/cp-native-retirement-followup-20261031/audit.py` 进一步执行40项原始Thumb检查，覆盖原先作为替身的状态和控制helper。控制路径写位、立即读回再清位，没有发现等待循环。第二次控制tick无需重新读取状态即可callback(0)；两种playback路径也允许masked word7进入完成状态。这些是合成MMIO下的软件条件，不能给寄存器位赋予“硬件已完成读取”的含义，ACTIVE数据仍须保留。

## 完整功能仍缺

旧resource.c使用六份unit、两个槽、QUERY2至5及旧停止屏障，与单快门CP及新transport不兼容。上述私有单所有者组件已替代这部分模型，并让focus事件保持未处理。完整原生hook、菜单、诊断生产者及镜像尚未迁移，不能据私有组件编译通过宣称完整后端成立。

当前DMM默认来源0仅为capture-only，不能据此取得拥有权。完整实现还需原生句柄与来源ABI、菜单侧表消费者、未发布取消的AP资源管理集成、ACTIVE的真实退休及重复使用、音量存储一致性、完整AP/CP与容器构建，以及机身三种快门模式的实际音频验收。

所有上述私有输出是本机研究组件，不是可直接上传或安装的固件。没有用内置提示音或模拟器音频代替用户自定义声音的完成条件。
