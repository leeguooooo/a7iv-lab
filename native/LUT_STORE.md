`lut_store.c` 为导入后的编译 LUT 提供记录和持久化。已生成 Linux/AArch64 组件，并完成正常系统库的符号/结构静态核查；文件系统行为仍仅在主机临时目录验证，尚未接入真实 AP 进程、机内路径或菜单。数据格式与原厂 `/usr/data/lut/*.LUT` 不同，不能把本记录直接交给原厂文件读取器。

每条记录为 48,256 字节：256 字节固定小端头部加 48,000 字节 AP 整数路径数据。头部包含槽位、递增版本、源文件长度/CRC32、源/编译网格、夹取/饱和统计、UTF-8 文件名和明确的输入/输出颜色空间标签；完整记录另有 CRC32。CRC 用于发现意外损坏，不用于认证来源。记录包含自足的编译表及来源信息，原始 CUBE 字节保留在源介质，没有另存进此记录。

支持 16 个独立槽位。正常记录及上一份备份合计约 1.47 MiB，不包括锁和异常遗留临时文件；不能据此假定相机设置分区当前有足够空间。目录必须事先由应用建立并独占管理，接口没有默认机内路径。

保存流程：

1. 拷贝并核验输入记录，取得每槽独占文件锁。
2. 核对当前有效版本与调用者的预期版本；冲突时不覆盖。
3. 若主记录有效，完整写入、同步并原子替换上一版备份。若此前从备份恢复，则保留该份已验证备份。
4. 将新记录写入独占创建的临时文件，处理短写/EINTR，fsync 并检查 close。
5. 原子替换主记录，再同步目录；全部成功才返回 OK。

load 会校验主记录；只有缺失/损坏时才尝试备份，并报告实际加载版本和是否来自备份。IO 错误不会被当成“不存在”。load 也会取得文件锁，可能创建锁文件，因此它不是可直接用于只读相机诊断的接口。

| 结果 | 调用者应如何处理 |
|---|---|
| OK | 文件保存确认完成；这还不是 CP 已应用或画面已更新 |
| CONFLICT | 重新加载当前版本，不能沿用旧预期覆盖 |
| BUSY | 当前槽位被另一个操作持锁，当前操作没有提交 |
| UNCERTAIN | 主记录已替换，但目录持久化未获确认；先 load 核对结果，再决定是否重试或发布到设备 |
| CORRUPT / INVALID / IO | 保持活动表；不要伪造成功或格式化存储 |

文件替换前的失败会清理本次实际创建的临时文件。临时名全部占用时不会删除既有文件；异常掉电留下的文件也不自动冒充已提交记录。目录同步失败后保留可核验的新主记录和旧备份，不通过回滚掩盖不确定结果。

14 项主机测试覆盖 CRC 与格式、版本冲突、独立槽、短写/EINTR、文件同步前/备份替换前/主记录替换前失败、主记录替换后同步失败、备份恢复、坏数据、锁冲突及临时名耗尽。真实公开 CUBE 的解析→转换→保存→新进程加载也已验证，读回数据与原厂读取器重放的 payload 一致。

这些结果不证明 VFAT 的物理掉电行为、机内 ABI 或 AP 调度正确。调用必须在非实时工作线程中执行；UI、CP 应用、资源生存期和成功发布通知仍需独立接入。不要在快门中断或帧回调中进行这些文件操作。
